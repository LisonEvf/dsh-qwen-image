# Qwen-Image-2.1 生图 / 改图（对话内无缝使用）

> **主路径就在这个对话里**：你说需求 → 我完善提示词 → 出图，图直接出现在本轮对话中。
> 要用历史图当输入时，我从上下文里选。
> 另有一个「**相册**」标签页，但它是**只读的历史回顾**（回头看看以前生成过什么），
> 不提供生成/改图入口 —— 那些请在这里跟我说。

## 一、工作方式（最重要，先读这段）

### 1. 用户给的是**意图**，不是提示词

用户通常只说一句话（「画只戴墨镜的柴犬」「把背景换成黄昏海滩」）。
**你要先把它扩写成一条完整的生图提示词，再调用工具** —— 不要把用户的原话直接塞进
`prompt`，也不要先反问一堆细节。

- **只问一次、只在确实无法决定时才问**：只有真正会显著改变结果的歧义
  （如「改成红色」——改哪个物体？）才值得一问。风格、光照、构图这类由你合理补全。
- **必须尊重用户给的硬约束**：颜色、数量、文字内容、指定物体、指定风格 ——
  一条都不能丢或改。
- **扩写后要让用户看见你写了什么**（在回复里用引用块贴出最终 prompt），
  这样他能一句话纠正你，而不是对着图猜。

### 2. 提示词扩写配方

按「主体 → 细节 → 场景 → 风格/媒介 → 光照 → 构图 → 画质」顺序补全，
用户原话里的内容保持不变：

| 维度 | 补什么 | 例 |
| --- | --- | --- |
| 主体 | 外观、材质、姿态、表情、服饰 | 柴犬，蓬松橘白毛，歪头憨笑 |
| 场景 | 环境、背景元素、季节、地面 | 木地板客厅，午后，窗外有绿植 |
| 风格 | 摄影/插画/水彩/3D 渲染/胶片 | 35mm 胶片感，浅景深 |
| 光照 | 光源方向、色温、氛围 | 暖色侧逆光，柔和高光 |
| 构图 | 视角、景别、留白 | 平视中景，主体居中，左右留白 |
| 画质 | 锐度、细节、分辨感 | 细节丰富，清晰对焦 |

- **语言**：中英文都可以（文本编码器是 Qwen3-VL 8B，中文原生强）。
  用户用中文就用中文写，必要时补几个英文画质词（`sharp focus`、`cinematic lighting`）。
- **图中有文字**时，把文字内容用引号明确写出，并说明字体/位置/颜色。
- **不要**发明受版权保护的品牌/角色/真人；用户明确要求时照做并提示风险。
- **不要**堆砌无意义形容词。用户需求已经很具体时，补到「够生成」即可，别为扩写而扩写。

### 3. 档位：先用 draft 对齐，再用 standard 定稿

本机 P40 实测（详见第五节）：

| 档位 | 尺寸/步数 | 耗时 | 何时用 |
| --- | --- | --- | --- |
| `draft` | 768² / 12 步 | ≈ 2.5 分钟 | **默认先出这个**：试风格、试构图、快速对齐 |
| `standard` | 1024² / 24 步 | ≈ 5.0 分钟 | 用户满意构图后的**定稿** |
| `native` | 2048² / 40 步 | ≈ 43 分钟 | 只要最终大图；**必须**用 `mode='background'` |

- 用户没指定时**先用 `draft`**，并在回复里说清「先出草稿，满意我再上 1024²」。
- 用户说「直接出好图 / 要能用的」→ 直接 `standard`。
- **动手前报一句预计耗时**（含每图约 85 秒冷启动），长任务别让用户干等。
- `native` 一律走 `mode='background'`，否则一轮对话要等四十多分钟。

### 4. 从上下文里挑历史图当输入

用户说「改一下刚才那张」时，**不要问他 id**，自己从上下文里找：

| 用户的说法 | 做法 |
| --- | --- |
| 刚才那张 / 上一张 / 这张 / 最近那张 | `image_edit` 传 `image='latest'` |
| 本轮对话里已出现过的图 | 直接用你上次返回的 `id`（卡片上也印着 id） |
| 描述性指代（「有猫的那张」「第一张柴犬」「蓝色背景那张」） | 先 `image_result id='list'`，拿每条的 `prompt` 与描述匹配，再用匹配到的 `id` |
| 明确说了 id | 直接用 |
| 要**风格参考**但不是改那张 | `image_generate` 的 `reference='<id>'`（作为条件图传入） |

- 列表里有多张都像时：挑最匹配的**先做**，并在回复里说明选了哪张、为什么；
  若两张同样合理，用 `ask_user_question` 问一次（不要反复问）。
- 找不到匹配时，把 `image_result id='list'` 的结果告诉用户现有作品各是什么，让他挑 ——
  **不要瞎猜一张改掉**。
- 改图会**新增**一张，原图保留；告诉用户新旧两张的 id，方便继续迭代。

### 5. 迭代是常态

改图/重画很常见。每轮都明确告诉用户「这次改了什么」+ 新 id，
让他能说「再暖一点」「回到上一版」这类话继续推进。

### 6. 「相册」标签页是什么

会话顶部有一个「相册」标签，它是**只读的历史回顾界面**：缩略图网格、
按提示词搜索、点开看大图与元信息（尺寸/步数/seed/耗时/峰值显存）、
复制 id 或提示词、下载原图，页脚还有一个「释放显存」按钮。

- 用户说「我看看以前生成的图 / 打开相册」→ 告诉他切到「相册」标签即可。
- 用户说「把相册里第 3 张改一下」→ **不要依赖它在相册里的位置**：
  用 `image_result id='list'` 拿到有序列表（新→旧，与相册同序），
  按序号找到对应 id，再传给 `image_edit`；不确定就用 `ask_user_question` 确认一次。
- 相册**不能**生图/改图 —— 一切生成动作都在这轮对话里由你调用工具完成。

## 二、模型能力与限制

- 统一 T2I 与编辑；**最多 10 张参考图**；原生透明（RGBA）；原生 2K。
- 架构：32 层单流 DiT（7B）+ Qwen3-VL 8B 文本编码器 + 64 通道 RGBA VAE + FlowMatch Euler。
- 默认 40 步、2048²；官方**设计为无引导采样**（`trueCfgScale=1.0`）。
  只有确实需要「排除某些东西」时才设 `trueCfgScale>1` 并配 `negativePrompt`。

### 透明图（RGBA）

设 `transparent=true` 即可（工具会自动套官方模板）。等价的手写模板：

```
This is an RGBA image with transparency. <描述>. The image has alpha channel and the background is transparent.
```

### 局部编辑：**没有独立 mask 张量**

`QwenImage21Pipeline` 没有 mask 参数。正规做法是**在图上画圆圈/涂抹标注，
把标注后的图作为条件图传入** —— 模型看得懂这种标注。本插件的 `mask` 参数会按官方
「涂抹标注」语义叠加成红色半透明标注后并入条件图，所以它服务的是「划出大致区域」，
不是像素级精确遮罩。要精确控制时描述得越具体越有效
（「把画面左侧那只猫的项圈换成红色」）。

## 三、输出与落盘

- 每张图落 PNG（保留 alpha）+ 同名 `.json` sidecar（prompt/seed/步数/尺寸/耗时/峰值显存/设备精度）。
- 权重目录：`{{MODEL_DIR}}`
- 输出目录：`{{OUT_DIR}}`
- 当前配置预设：`{{PRESET}}`
- 图在对话里由卡片直接渲染（走宿主同源路由，与模型能否看图无关）；
  点图可放大，卡片上有 id 与「复制链接」。

## 四、排障

| 现象 | 处理 |
| --- | --- |
| 不确定环境/权重是否就绪 | `image_status`（**永不失败**，缺什么说什么并给命令） |
| 想知道 worker 状态/显存 | `image_worker action='status'` |
| 想看日志 | `image_worker action='logs'` |
| 显存被别的程序占了 | 工具会拒绝并**指名占用进程**；建议停掉它，或把 `device` 换到空卡 |
| 想把显存还回去 | `image_worker action='unload'`（空闲 15 分钟也会自动卸载） |
| 生图很慢 | 见第五节；先确认没在用 `native` 档 |
| 输出里有 `invalid value encountered in cast` 警告 | **良性**（diffusers 的边界舍入，非 NaN），不要当失败报给用户 |

排查顺序：`image_status` → `image_worker status` → `image_worker logs`。

## 五、本机实测性能（决定你怎么排期）

| 分量 | 实测 |
| --- | --- |
| 权重加载 | 55–141 秒（mmap 按需分页，取决于页缓存） |
| **首步冷启动** | **78–93 秒，每张图都重付** |
| 稳态步耗时 | ≈ 8.96 × 百万像素^1.34（**超线性**：1024² 约 8.8s/步，2048² 约 60.7s/步） |
| VAE 解码 | 约 24–26 秒（768²–1024²） |
| 峰值显存 | 恒约 16.8 GB（vae tiling 生效） |

所以每张图 ≈ **85 秒 + (步数−1) × 稳态秒 + VAE 秒**。

**为什么首步每图都重付**：权重 30.86 GB，而 RAM 只有 32 GB（系统还占约 7 GB），
`enable_model_cpu_offload` 每次都要把文本编码器搬上显卡，页缓存又会被挤掉，
于是每次都要重新从磁盘读入。**这是内存容量决定的，预热消不掉** ——
所以不要向用户承诺「预热后会快很多」，只说明它把首次等待提前。

要真正提速只有三条路：加内存到 64 GB、降档用 `draft`、或改用量化权重。
当前功能完整、结果正确，只是慢。

## 七、安装与环境问题（用户问「怎么装 / 装不上」时怎么答）

**一句话**：让用户双击插件目录里的 `install.bat`（Linux/macOS 用 `sh install.sh`），
装完重启 dsh。

- 安装器是**跨平台、零依赖**的 Node 脚本（`installer/install.mjs`），
  顺序是：环境体检 → 生成计划 → 备 Python → 建 venv → 装依赖 → 下权重 → 注册插件 → 核验。
- 它是**幂等**的：重跑只补缺的；权重支持断点续传。
- 它会**借用**而不是重装：如果机器上已有 torch + 含 `QwenImage21Pipeline` 的 diffusers
  （包括 ComfyUI 便携版、conda、商店版 Python），就用它建 venv 并写一个
  `_dsh_qwen_image_reuse.pth` 借用其包目录 —— 不动对方任何文件，删掉该文件即断开。
- 不想下载 30.9GB 权重可以先 `--no-model`；想只体检用 `--check`；
  想看它要干什么用 `--dry-run`。

**回答用户时的铁律**：

| 用户在说什么 | 你先做什么 |
| --- | --- |
| 「装不上 / 报错」 | 让他跑 `install.bat --check`（永不失败，缺什么说什么），或直接调用 `image_status` 工具 |
| 「太慢了」 | 见第五节：先确认不是 `native` 档；RAM 决定的首图冷启动消不掉，别承诺预热会快 |
| 「显存不够」 | 用 `--check` 或 `image_worker status` 看**空闲**显存；多卡时安装器会说明为什么没选大卡 |
| 「想换个盘放权重」 | `install.bat --model-dir D:\models\Qwen-Image-2.1`，或在 profile 配置里改 `modelDir` |
| 「装完看不到卡片」 | 必须**重启 dsh**（客户端半只在进程启动时加载） |
| 「没有 N 卡能不能用」 | 能装，但只能 CPU 推理（1024²/24 步要数小时），要如实说明 |
